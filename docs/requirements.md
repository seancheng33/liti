# 砺题 Liti 需求规格说明

> 立项日期 2026-10-28，v1.0.0 发布 2026-11-03。
> 这份文档说明「要做成什么样」与「有意不做什么」。逐条需求的实现与验证见 [acceptance.md](acceptance.md) 的「需求对照」（74 条）。

## 1. 背景

学校里的小测验有个反复出现的麻烦：老师出卷要排版、印卷、收卷、人工判分、登分、算平均分，一套流程下来，两节课的测验要花掉一晚上的时间。市面上的在线考试系统多数面向培训机构，要联网、要买账号、数据在别人服务器上；学校机房又常常只有局域网。

所以要做的东西很简单：**把机器放到局域网里，老师浏览器打开就能出卷、考试、判分、看分析。**

目标用户是任课老师本人，不是教务部门。所以它不追求"全校统一平台"那一套，也不做排课、学籍、家校沟通。

## 2. 目标与成功标准

| 目标 | 度量 | v1.0 实测 |
|---|---|---|
| 出卷到出分全流程在浏览器内完成 | 不需要纸、不需要 U 盘传文件 | 已达成 |
| 一个班开考不出现 5xx | 并发压测错误数为 0 | 2 核 2G 上六场景 0 错误 |
| 断网、切屏、误关页面不丢答案 | 答案最终一致率 | 按题合并 + 重试 + 快照兜底 |
| 成绩不会提前泄露 | 未发布时接口不下发分数 | 服务端置 null，非前端隐藏 |
| 部署门槛低 | 一台机器一条命令起来 | Docker 单容器，SQLite 零配置 |

## 3. 范围

### 3.1 做

| 模块 | 内容 |
|---|---|
| 题库 | 单题录入、Excel 批量导入导出、分类、查重、配图、软删除 |
| 组卷 | 固定选题目 / 按分类随机抽题，题量 1–100，选项乱序、题序乱序 |
| 答题 | 倒计时、自动保存、标记、暂停（练习卷）、答题卡、交卷 |
| 判分 | 客观题自动判分、逐题解析、分数与解析受控发布 |
| 练习 | 自助随机卷、错题库、按错题组卷 |
| 学情 | 成绩册（含缺考）、逐题 P/D 值、选项分布、分数段、导出 Excel |
| 人员 | 三种角色、学生分组、名单批量导入、密码重置码 |
| 考试管理 | 时间窗口、统一收卷、实时监考、违规计数与撤销 |
| 审计 | 42 个动作留痕、筛选、CSV 导出 |
| 部署 | Docker 单容器、SQLite / MySQL 双驱动、备份恢复脚本 |

### 3.2 不做（有意如此）

| 不做 | 原因 |
|---|---|
| 主观题自动批改 | 做不准，不如不做。目前只支持单选 / 多选 / 判断 |
| 公网多租户、学校间隔离 | 定位是单校局域网，多租户要引入租户字段与全套隔离测试，收益不成正比 |
| 排课、学籍、家校通知 | 那是教务系统的事，接进来就是另一个项目 |
| 手机 App | 考试场景需要大屏，响应式 Web 够用；Electron 桌面壳是给「物理级防切屏」留的 |
| 离线单机版（无服务端） | 判分和成绩必须集中，否则老师要挨个收数据 |
| 富文本题干 | 支持配图 + 纯文本。富文本会带来粘贴样式污染、导出错乱、XSS 面积 |
| 视频 / 音频题 | 同上，且局域网带宽不可控 |

## 4. 角色

| 角色 | 能做什么 | 边界 |
|---|---|---|
| 学生 `student` | 看自己可见的卷、答题、看自己成绩与错题 | 看不到别人的答卷；名单外的卷一律 404 |
| 教师 `teacher` | 题库、组卷、看成绩分析、监考、管学生账号与分组 | 只能管学生，不能碰其他教师和管理员 |
| 管理员 `admin` | 全部功能 + 用户管理 + 系统设置 + 审计日志 | 审计日志仅管理员可见 |

权限判定全部在服务端。前端隐藏按钮只是顺手，不作为安全措施。

## 5. 需求分组

74 条明细在 [acceptance.md](acceptance.md#需求对照)，按模块归组如下。

| 组 | 条目 | 要点 |
|---|---|---|
| 题库 | 1–2、16–17、26–27、40 | Excel 12 列模板可回导；查重用 `content_hash`；删除是软删除，不伤历史卷 |
| 组卷 | 3–5、22 | 随机抽样可多条规则；草稿预览不落库 |
| 答题 | 7–9、28–31 | 默认每卷 3 次、可按卷改；暂停时服务端抹掉题面 |
| 防作弊 | 6、8、15、32、71–73 | 选项乱序 + 题序乱序 + 切屏计数 + 物理级壳（Electron） |
| 考试 | 42–49 | 时间窗口、统一收卷、成绩与解析分开发布 |
| 成绩与学情 | 13–14、47、52–56 | 缺考保留；P 值分母是实考人数；D 值样本 < 8 给 null |
| 人员 | 39、50–51 | 学号/班级必须是 varchar（MySQL 的 TEXT 不能建索引） |
| 练习与错题 | 12、35–37 | 错题按人隔离，接口不收 userId 入参 |
| 可靠性 | 57–59 | 断网重试、交卷快照、超时后不可补分 |
| 监考与审计 | 60–70 | 心跳 90s 判掉线；暂停中不判掉线；违规可撤销并退额度 |
| 运维 | 10–11、33–34、74 | 双库、SSO 预留、备份恢复、密码找回 |

## 6. 非功能要求

| 项 | 要求 | 实测 / 现状 |
|---|---|---|
| 部署环境 | 单台 Linux，2 核 2GB 起 | 测试机即 2 核 2GB |
| 并发 | 8 并发混合负载下错误率为 0 | 六场景 0 错误（MySQL exam-flow 有 1 次瞬时失败）；答题保存 977 rps（SQLite）/ 551 rps（MySQL） |
| 首屏 | 局域网内 2 秒内可交互 | Vite 构建产物由后端托管 |
| 数据 | 断电不丢已交卷数据 | WAL + 交卷快照；备份用 `.backup()` 热备 |
| 安全 | 密码 argon2、会话只存哈希、登录限流 | 63 项安全验收双库全绿 |
| 兼容 | Chrome / Edge 最近两个大版本 | 答题依赖 `visibilitychange`，老浏览器不保 |
| 可维护 | 类型检查零错误、测试可复跑 | `tsc --noEmit` 干净，单元 + 集成 72 项 |

## 7. 已知限制

写在这里，免得用的人踩了以为是 bug。

1. **Web 端防切屏防不住决心**。浏览器能做的只有检测失焦 + 遮罩 + 计数，Alt+Tab 到别的窗口、用第二台设备查答案，都拦不了。要物理级隔离只能上 Electron 壳（已有），或者干脆用机房管控。
2. **题序乱序会改变「第几题」的指代**。开了之后老师讲评得按题目说，不能按序号说。所以默认关闭。
3. **难度维度已移除**。早期版本有 1–3 级难度，后来发现老师填得随意、统计也不好用，v0.8 之后统一改成用 P 值 / D 值说话。
4. **主观题不支持**。题干可以放图，但答案只能是选项。
5. **审计日志只增不改**。清理是软清理（保留 `audit.purge` 自身），设计上不提供删单条。
6. **SSO 只做了数据结构预留**，OIDC 的 `start` / `callback` 端点还没有实现。

## 8. 需求变更记录

| 时间 | 变更 | 缘由 |
|---|---|---|
| v0.4 | 加「每卷最多 3 次作答」 | 学生反复刷同一张卷，成绩失真 |
| v0.7 | 成绩与解析改为受控发布 | 有人提前看到分数，考场秩序乱 |
| v0.8 | 砍掉难度维度 | 填得随意，统计无意义，改用 P/D 值 |
| v0.8 | 作答次数改为按卷配置 | 练习卷需要不限次，考试卷只能一次 |
| v0.9 | D 值样本 < 8 人返回 null | 人太少算出来是噪音，不如不给 |
| v0.11 | 违规计数改为可撤销 | 误报（输入法弹窗、系统通知）会误伤，撤销要退额度 |
| v0.13 | 题序乱序默认关闭 | 会改变「第几题」的指代，得老师知情后自己开 |
| v1.0 | 功能冻结 | 再改就要动数据库结构和验收基线，先稳住 |
