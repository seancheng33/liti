# 砺题 Liti v1.0.0 发布说明

发布：2026-11-03 · 上一版 v0.14.0 · [变更日志](../../CHANGELOG.md)

## 这是什么

一套装在局域网里的刷题与考试系统。老师在浏览器里出卷、发卷、看成绩，学生在浏览器里答题，服务端自动判分并给出逐题分析。不需要联网，不需要买账号，数据在自己机器上。

三种角色：管理员、教师、学生。一台 2 核 2G 的机器够一个学校用。

## 这一版意味着什么

**功能冻结。** v0.14 之后不再加新功能，这个版本是把已有的东西收干净：修掉测试基础设施的隐患，把双库全量复跑了一遍，把文档补齐，把镜像版本号固定下来。

也就是说：从这版开始，升级只会有修 bug 和小改进，不会有「昨天还能用的功能今天没了」这种事。

## 装起来

最短路径，Docker：

```bash
docker run -d --name liti --restart unless-stopped \
  -p 8080:8080 \
  -v liti-data:/app/data \
  -e SESSION_SECRET=$(openssl rand -hex 32) \
  liti:1.0.0
```

然后浏览器打开 `http://<机器IP>:8080`，用 `admin` / `admin123` 登录，**第一件事是改密码**。

其他装法（不用 Docker、用 MySQL、开机自启、桌面壳）见 [deployment.md](../deployment.md)。

## 从 0.x 升上来

数据库迁移会自动跑，不用手动执行。需要注意两件事：

1. **备份先做**。`sh scripts/liti-backup.sh` 跑一次，确认备份文件生成了再升级。
2. 如果之前手改过配置文件，升级前对比一下 `docs/deployment.md` 第 8 节，看有没有新增项。

从 `v0.14.0` 升到 `1.0.0` 没有表结构变化，把容器换成新镜像就行。

## 能做什么

| 模块 | 要点 |
|---|---|
| 题库 | 单题录入、Excel 批量导入导出（12 列，导出的能直接回导）、分类、查重、配图 |
| 组卷 | 固定选题目 / 按分类随机抽，题量 1–100，选项乱序、题序乱序 |
| 答题 | 倒计时、自动保存（断网不丢）、标记、答题卡、暂停（练习卷） |
| 考试 | 时间窗口、统一收卷、成绩与解析分开发布、缺考保留 |
| 监考 | 谁在考、谁掉线、违规几次，误报可撤销 |
| 学情 | 成绩册、逐题 P 值 / D 值、选项分布、分数段、导出 Excel |
| 练习 | 自助随机卷、个人错题库、按错题组卷 |
| 人员 | 学生分组、名单批量导入、学号班级、找回密码 |
| 审计 | 42 个管理动作留痕，可按人/按对象/按时间查，导出 CSV |

## 已知限制

买之前该知道的，都写在这里。

1. **防切屏防不住决心。** 浏览器只能检测失焦然后遮罩计数，`Alt+Tab`、旁边的手机、第二台设备都拦不了。要物理隔离用 Electron 桌面壳（已附带），或者靠机房管控。
2. **只支持客观题。** 单选、多选、判断。主观题做不准，没做。
3. **题序乱序默认关着。** 开了之后「第 3 题」在师生之间指代的不是同一道题，讲评得按题目说。
4. **没有手机 App。** 响应式网页，手机上能看但不适合答题。
5. **SSO 只留了数据结构。** OIDC 的登录跳转还没实现。
6. **审计日志只增不改。** 清理是软清理，不提供删单条。

## 这一版的验收

都是实跑的，不是估算。

| 项 | 数量 | 结果 |
|---|---|---|
| 接口验收（v2–v14，SQLite） | 699 | 全绿 |
| 接口验收（v2–v14，MySQL） | 670 | 全绿 |
| 界面验收（v0.14 找回密码全链路，双库） | 24 | 全绿 |
| 单元 + 集成 | 72 | 全绿 |
| 安全黑盒用例 | 63 | 全绿 |

性能基线（2 核 2GB，并发 8）：

| 场景 | SQLite | MySQL |
|---|---|---|
| 答题自动保存 | 977 rps / p95 10ms | 551 rps / p95 19ms |
| 完整考试流 | 43 流/秒 | 23 流/秒 |
| 登录 | 12 rps | 11 rps |

登录慢是 argon2 故意调慢的，防离线爆破，不是性能问题。按「完整考试流 23 流/秒」这个吞吐推算，200 人陆续开考的总耗时在十几秒量级；但开考本身只是一个请求，真正的时间会花在「一个班同时点交卷」的那一刻，那个场景建议分批提醒，或者干脆用统一收卷。
