# 安全测试与加固记录

> 测试日期：2026-11-01　测试对象：v0.5（commit `aeb4dd2` 之后的安全加固版）
> 测试方式：**代码审计 + 黑盒接口测试**（不依赖源码知识，从外部打）
> 复现：`LITI_BASE=http://<host>:8080 node liti-sec.mjs`（63 项，SQLite / MySQL 双库各跑一遍）

---

## 1. 结论

| 维度 | 结果 |
|---|---|
| 黑盒安全用例 | **63 / 63 通过**（SQLite、MySQL 各一遍） |
| 功能回归 | v6 105/105、v5 84/84、v4 49/49、v3 40/40（双库） |
| 发现并修复 | 高危 3 项、中危 4 项、低危 3 项 |
| 未修复（已评估可接受） | 3 项，见第 5 节 |

本次审计前，系统在「越权」和「会话生命周期」两块有明显缺口；修复后这两块是本系统目前最扎实的部分。

## 2. 已修复的问题

### 2.1 高危

**H1 `GET /api/papers/:id` 没有可见性校验**
任何登录用户（含学生）带上自增 ID 就能读到**草稿卷、指定给别人的限定卷、别人的练习卷**，返回体里还带 `audience_user_ids`（可见名单）、`random_config`（抽题规则）、`created_by`。
影响：枚举 1..N 即可摸清全站试卷结构与名单。

修复：学生视角只允许「自己创建的练习卷」或「已发布且确实可见的正式卷」，其余一律 404；同时剥掉名单与抽题规则。

**H2 停用账号不生效**
`authenticate()` 只判断「有没有登录」，不看 `status`；`requireRole()` 才看。而学生日常用的答题、错题本、成绩、试卷列表全走 `authenticate`。
实测：管理员停用某学生后，该学生旧会话在 5 个接口上**全部照常 200**，还能继续答题交卷。
影响：老师停用作弊学生完全无效。

修复：`authenticate()` 内校验 `status !== 'active'` → 403；停用/重置密码时顺手清掉该账号的全部会话。

**H3 登录接口无速率限制**
密码最短 6 位，可以无限次尝试。
影响：在线爆破 + 撞库。

修复：内存滑动窗口双维度限流 —— 「用户名 + IP」8 次 / 10 分钟，「单个 IP」30 次 / 10 分钟（挡住换用户名撞库）；命中返回 `429` + `Retry-After`；登录成功即清零。

### 2.2 中危

**M1 他人练习卷可被开考**
`startAttempt()` 对 `practice=1` 的卷子跳过了可见性校验，而练习卷是 `review_mode='immediate'`（逐题即时给答案）。
实测：B 拿 A 的练习卷 ID 能开考，并直接拿到 `isCorrect` 与解析。
修复：练习卷只有创建者本人能答，其他人 404。

**M2 学生可浏览整个题库**
`GET /api/questions` 只 `authenticate`，没 `requireRole`。学生能翻到全库题干（不含答案，但仍属提前泄题）。
修复：列表接口限 `admin` / `teacher`。

**M3 缺少基础安全响应头**
无 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`。
影响：上传文件 MIME 嗅探、考试页被 iframe 套住做点击劫持。
修复：全局 `onSend` 钩子补 `nosniff` / `SAMEORIGIN` / `same-origin` / `Permissions-Policy`。

**M4 改密码、重置密码后旧会话不失效**
「密码泄露了，我改个密码」踢不掉对方手上的会话。
修复：改密码时清空该账号全部会话并给当前设备重发 cookie（不掉线）；管理员重置密码时清空全部会话。

### 2.3 低危

**L1 题干/选项无长度上限** —— 20 万字符的题干能正常入库，会把列表、导出、页面渲染拖垮。
修复：`stem ≤ 5000`、`explanation ≤ 20000`、选项 `≤ 2000`、标签 20 个 × 32 字、图片 9 张 × 500 字。

**L2 `/uploads/` 路径穿越返回 500** —— `@fastify/send` 抛的 `ForbiddenError`（带 `statusCode`）没被错误处理接住，兜成 500 并刷错误日志。没有读到文件，但会污染日志、误导排错。
修复：错误处理识别 `statusCode` 在 4xx 区间的异常，按原状态码返回（404/403）。

**L3 登录响应时间差可枚举用户名** —— 账号不存在时直接跳过 argon2 校验，响应明显更快。
修复：账号不存在时也拿一个固定 dummy hash 跑一次校验，抹平时间差。

## 3. 验证过的点（本次测试覆盖，无需改动）

- **会话**：32 字节随机 token，库里只存 sha256；Cookie `HttpOnly` + `SameSite=Lax`；登录重新签发（无会话固定）；登出后旧 token 立即失效
- **垂直越权**：学生访问用户/分组/统计/设置/上传/导出共 13 个管理接口全部 403；教师不能建教师、不能改管理员
- **水平越权**：读/改/交他人答卷全部 403；名单外学生读限定卷、开限定卷全部 404
- **答案红线**：考试模式答题中不下发 `isCorrect` 与解析；暂停时题面与选项在服务端就抹掉；公开预览接口从不含答案，草稿卷与限定卷在公开接口一律 404
- **注入**：全项目无原生 SQL（Kysely 参数化），`' OR 1=1 --` 载荷未改变查询结果；前端无 `dangerouslySetInnerHTML`
- **上传**：仅 admin/teacher；MIME 白名单 + 固定扩展名 + UUID 文件名，不存在路径穿越
- **信息泄露**：500 不返回堆栈与路径；错误响应不暴露服务端目录

## 5. 未修复项与已知边界

| # | 项 | 评估 |
|---|---|---|
| 1 | **未加 CSP** | SPA 用 antd，内联样式较多，强 CSP 容易误伤；已用 `X-Frame-Options` + `nosniff` 覆盖主要风险。要加 CSP 需先做 nonce 改造，成本大于收益 |
| 2 | **无 CSRF token** | 评估为低风险：认证 Cookie 是 `SameSite=Lax`，且所有写接口只接受 `application/json`，跨站表单（只能发 `urlencoded`/`multipart`/`text`）会被 Fastify 以 415 拒绝。若将来新增 `multipart` 或 GET 写操作，需重新评估 |
| 3 | **限流是进程内内存** | 单容器单进程有效；多实例部署时每个实例各算各的。真要横向扩展应换成 Redis 计数 |
| 4 | **密码策略仅「≥6 位」** | 由管理员建号，内网场景可接受；若对外开放建议提高到 8 位并加弱密码黑名单 |
| 5 | **`SESSION_SECRET` 未被代码使用** | 会话用的是随机 token + sha256，不需要签名密钥。该配置项是预留位，文档里不再称其为「会话签名密钥」 |
| 6 | **登录失败计数按用户名+IP** | 分布式 IP 攻击（僵尸网络）仍可绕过；内网场景不在威胁模型内 |

## 5.1 审计日志视角下的安全约定（v0.12）

审计日志本身是**敏感数据**：里面会出现「谁给谁重置了密码」「谁改了哪个学生的班级」「哪份卷子被谁删了」。所以它自己也必须按敏感数据对待。

| 约定 | 做法 |
|---|---|
| 只有管理员能读 | `GET /api/audit`、`/meta`、`/export`、`POST /purge` 全部 `requireRole(user, 'admin')`。教师与学生一律 403 —— 教师能看到这些东西，等于把横向的账号操作全打开了 |
| 不记密码 | 重置密码只记「谁重置了谁的」，`detail` 里没有明文也没有哈希。登录失败只记 `reason`（`no-such-user` / `bad-password` / `disabled`），不记尝试的密码 |
| 不记答案与解析 | 审计只收管理动作，学生的答题流水根本不进表 |
| 日志写失败不阻断业务 | `writeAudit()` 内部吞异常。宁可漏一条，也不能让发布试卷 / 交卷失败 |
| 导出留痕 | `GET /api/audit/export` 自己也会写一条 `audit.export`，记下导出了多少行 |
| 清理留痕且不可抹除 | 先写 `audit.purge`，再删旧记录，且 `WHERE action != 'audit.purge'` —— 清理记录永远活着 |
| IP 来源 | 与登录会话记录同源（`request.ip`），便于追「从哪台机器操作的」。经过反代时需要在 nginx 上正确设置 `X-Forwarded-For` 并让 Fastify 信任代理，否则记下来的全是反代地址 |

**演练过的攻击面**（v0.12 验收 D 组）：

- 未登录直接打接口 → 401
- 学生 / 教师拿自己的会话打接口 → 403（不是 404，日志存在性是公开信息，没必要藏）
- 教师直接输入 `/audit` 地址 → 页面能进，但接口 403、列表为空。**权限靠服务端，前端隐藏只是顺手**
- 学生把自己的 `actorId` 塞进查询参数 → 无效，接口不接受「查别人」之外的越权维度（`actorId` 只是筛选条件，前提是角色已经是 admin）

**未做**：审计日志没有写前校验（比如拒绝含 `
` 的 targetLabel）。风险很低（写进去的都在自己人手里，展示时 React 也会转义），但如果将来做日志外发 / 邮件告警，需要在出口处再过一遍。

## 6. 复现命令

```bash
# 安全用例（63 项）
docker cp liti-sec.mjs <容器>:/app/server/
docker exec -e LITI_BASE=http://127.0.0.1:8080 -w /app/server <容器> node liti-sec.mjs

# 功能回归
docker exec -e LITI_BASE=http://127.0.0.1:8080 -w /app/server <容器> node liti-features-v6.mjs
```

脚本全部只走 HTTP 接口，不直连数据库，也不依赖源码结构 —— 换实现后同样适用。
