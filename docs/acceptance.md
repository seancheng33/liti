### 写这两个脚本时踩的坑（下次直接用）

- **antd 关闭过的下拉仍留在 DOM 里**（`display:none`）。数选项要限定在当前展开的那个：`.ant-select-dropdown:not(.ant-select-dropdown-hidden) .ant-select-item-option`，否则会把分类下拉的 9 项一起数进来（9+7=16）。
- **不可展开的行也有占位图标**（`.ant-table-row-expand-icon-spaced`，是个 `<span>`）。点它永远没反应，选择器必须 `:not(.ant-table-row-expand-icon-spaced)`。
- **清理接口的时间基准要用服务器时间**：本机与容器时钟差 2 秒，用 `Date.now()` 当 `before` 会被判成「清理未来」。脚本开头 `await serverNow()` 取 `GET /api/health` 的 `time`。
- **MySQL 的 UPDATE 把值设成一样的会报 0 行受影响**，SQLite 报 1 行。凡是要断言「更新了 N 行」的用例，必须真的改值（比如把分类改成 `null`），否则两边数字对不上。

## v0.10 答案保存容错验收（34 项接口 + 18 项断网行为）

脚本：`E://workbuddy//网站优化//liti-features-v10.mjs`（接口级，双库各跑一遍）
界面：`E://workbuddy//网站优化//liti-shot-v10.mjs`（CDP 掐断 `/answers`，模拟答题中途断网）

**这组用例的核心不是「接口返回 200」，而是「断网时学生答的题到底算不算分」。** 界面脚本用 CDP 的 Fetch 域把 `PATCH /answers` 逐个 fail 掉（`ConnectionRefused`），其他请求照常放行——这正好是考场的真实故障形态：答案存不上，但交卷那一刻网络通了。

| 分组 | 覆盖点 |
|---|---|
| A 交卷快照（接口级） | 全程不发一次 PATCH、只靠交卷快照也能拿满分 30/30；`applied` 返回实际写入条数；只带 1 题时其余按未答计（10 分不是 30 分）；**快照能覆盖先前 PATCH 存错的答案**；卷外 `questionId` 静默忽略（`applied` 只数本卷的）；非法选项被过滤后合法那个照常判对；不带 body 仍能交卷（自动收卷路径）；已交卷再交 400（快照不能用来改分） |
| B 超时后快照无效 | 2 秒卷开考 → 等 2.6 秒 → 带快照交卷 400「已超过答题时间」；**分数仍为 0**；交卷原因记 `timeout`。快照写入必须在超时检查之后，否则「拖到最后一秒塞答案」就成立了 |
| C 单题保存回归 | 保存 200；读得回来；可以清空；卷外题目 404；**暂停中 400 且文案含「暂停」**（前端据此判定终态、停止重试）；交卷后 400 |
| D 入参校验 | `answers` 非数组 400；`questionId` 非整数 400；选项 id 非整数 400；超过 1000 条 400（挡住畸形请求）；校验失败若干次后仍能正常交卷 |

## 已知边界

1. 多选判分为「全对得分」（少选不得分）。
2. 浏览器环境的防切屏是「检测 + 遮罩 + 惩罚」，物理级拦截依赖 Electron 壳。
3. 题目配图走 base64 上传，单张 ≤4 MB；暂不支持拖拽多文件批量上传。
4. 纯图片题（题干留空、只有配图）不进查重范围。
5. 公开接口（`/api/public/*`）只暴露**数字统计**与**已发布试卷的题面**，不含作答者信息、不含答案与解析；草稿卷一律 404 —— 这是有意的，不要把公开预览扩成「带答案预览」。
6. 草稿预览（`draft-preview`）按当前表单实时抽题，抽出来的题与真正创建时**不保证一致**（随机抽样每次都不同）；它的用途是看版式与题量，不是确认题目。
7. 帮助文档是前端静态内容，改文案需重新构建前端镜像。
8. **「删除题目」是软删除**：记录仍在库里（`status='archived'`），只是不再出现在题库列表、不再参与组卷与查重。想彻底清掉得直接动库 —— 这是为了保住历史试卷的可读性，属于有意设计。
9. **作答次数上限（v0.8 起按卷配置）**：`paper.max_attempts` 默认 3，建卷时 1–99 可填；只统计「已交卷 / 已超时」的答卷，开考后不交卷一直挂着的那次不占次数，重新进入会复用同一张进行中的卷（题序、答案都还在）。练习卷不受限，`remaining_attempts` 下发 `null` 表示「不限次数」——**前端判 `null` 必须走 `=== null` 分支**，`|| 0` 或 `?? 0` 会把练习卷显示成「次数已用完」。改默认值要动 `paper/service.ts` 的 `MAX_ATTEMPTS_PER_PAPER`（现在只是兜底值）并重新构建。
10. **暂停没有总时长上限**：暂停期间不判超时、不计违规，理论上可以一直停着。若将来要加「最多暂停 N 次 / 累计 M 分钟」，需要在 `attempt` 上加计数字段（现有 `paused_total_ms` 已记录累计毫秒，可直接拿来做判断）。
11. **可见范围是「白名单」语义**：`selected` 模式下名单为空等于谁都看不见，所以发布时强制至少选一人；名单外的学生访问试卷详情一律 404 而不是 403（不暴露该卷存在）。
12. **切屏检测依赖浏览器事件**：隐身窗口、部分国产浏览器的「多标签预览」可能不触发 `visibilitychange`；`window.blur` 会在点击浏览器地址栏时也触发，属误报方向的安全取舍（宁可多报）。物理级拦截仍然只有 Electron 壳能做到。
13. **错题「答对即订正」只认一次**：做对一次就移出待订正，不要求「连续对 N 次」。想更严格（比如连对 3 次才算掌握）需要给 `wrong_question` 加连续正确计数，现有结构没有这个字段。
14. **错题本只在交卷判分时写入**：中途退出、还没交的答卷里的错题不会进来（否则等于提前告诉你哪题错了）。
15. **分组是引用不是快照**：改分组会立刻影响所有挂了该分组的已发布试卷。这是设计目标，但反过来说——把学生踢出一个组，他手上正在做的卷子会立刻打不开（进行中的答卷仍可继续，因为开考时已经校验过了）。
16. **教师能管学生但不能管同伴**：教师无法创建教师/管理员、无法修改任何账号的角色、无法重置管理员密码。这条边界在服务端，前端隐藏按钮只是辅助。
17. **题库导出不含配图**：导出用 12 列（与导入模板一致）以保证「导出→改→导入」闭环，代价是题干/选项配图不会出现在表格里。需要连图备份时请直接备份数据库与 `data/uploads`。
18. **考试时间窗口只管「开考」与「截止」**：`start_at` 之前学生打不开卷、`end_at` 之后不能再开考，但**已经在答题的人**不会被立刻踢出去——他们的 `deadline_at` 在建卷时就被截断到 `end_at`，靠倒计时与 sweeper 收口。要「立刻清场」用强制收卷 `POST /:id/close`。
19. **sweeper 是单进程定时器**：30 秒扫一次，且只在服务进程活着时跑。多实例部署时每个实例都会扫（幂等，不会重复判分，因为判分前会先确认 `status='in_progress'`），但扫的节奏仍受进程数影响。服务停机期间到点的答卷，重启后第一轮扫描补判。
20. **「未公布成绩」不等于「答完看不到任何东西」**：学生仍能看到自己选了什么、题目标记、交卷状态，只是分数与对错为 `null`。这是刻意的——连题都不给看会让考生怀疑卷子丢了。
21. **`review_mode=never` 是单程开关**：设了永不公布，后续即使把 `analysis_published` 打开也不会下发答案，必须先改 `review_mode`。
22. **每题分值只有一档**：`per_question_score` 是整卷统一分值，`paper_item.score` 理论上可以逐题不同，但 UI 与导入都只提供统一入口。要「前 5 题 2 分、后 5 题 4 分」得直接改库或加新入口。
23. **成绩册的「应考名单」是导出那一刻算的**：导出前把学生移出分组，他就从表里消失了；导出后归档试卷不影响已导出的文件。要留底请导出后自行存档。
24. **归档不是删除**：`status='archived'` 只影响列表可见性与组卷引用，答卷、判分、错题记录全在。真要清数据得手工动库（且会破坏成绩可追溯性）。
25. **班级是「标签」不是「实体」**：`user.class_name` 为自由文本，没有班级表、没有班主任、没有年级归并。好处是学校怎么命名都能录（「高一(3)班」「2026届3班」）；代价是「高一(3)班」和「高一（3）班」（全角括号）会被当成两个班，班级下拉里去重后排成两条。导入前请统一命名法。
26. **学号唯一但不强制必填**：`student_no` 可空（教师/管理员不填），也允许同一批学生暂时都没学号；有值时必须全校唯一。学号格式限 `[a-zA-Z0-9_-]`、≤32 字符——学号里带空格、斜杠或中文会在导出 Excel 时对不上任何学校花名册。
27. **学生导入是「逐行独立提交」**：与题库导入的整批事务相反。好处是 1000 人的表里有 3 行格式错，剩下 997 人照样进来；代价是**没有「撤销这一批」**——导错了只能按返回的 `ids` 批量删人，或者删库重来。导入前先跑一次 `dryRun=1` 预检。
28. **导入的默认密码是全校同一个**：`student123`。这是刻意的（教务要能把密码统一告诉学生），但意味着**名单里任何人拿到同学的用户名就能登进去**。正式上线前应改为「学号后 6 位」之类的规则，或导入后强制首次登录改密（当前未实现）。导入接口返回的 `defaultPassword` 只用来告知，不落库。
29. **按班级导出取的是「导出那一刻」的班级归属**：学生中途换班，之前导出的文件不会跟着变；导出后再改班级，旧文件仍是旧班。需要留底请导出后自行存档。
30. **班级字段变更不会迁移历史成绩**：成绩册按 `user.class_name` 的当前值归属，所以学生转班后，上学期的成绩册重新导出时会出现在新班里。真要按「当时的班级」归档，得在 `attempt` 上快照一份 `class_name`（当前未做）。
31. **「导入学生名单」只有 admin/teacher 能用**：`GET /api/users/template` 也做了鉴权（曾经漏过，学生能下载模板）。模板本身不含敏感数据，但接口边界要一致，别为了「方便」放开。
32. **成绩册的学号列可能是空的**：没填学号的学生导出后该列为空。教务通常靠学号排序点名，上线前请先补齐学号，或接受「按班级 + 姓名」核对。
33. **D 值需要样本量**：实考不足 8 人时，前后 27% 各凑不满一组，D 值一律返回 `null`（界面显示「—」）。5 个人的 D 值只可能是 0 或 ±1，给了反而误导。想看 D 值至少凑够一个班。
34. **P 值的分母是实考人数，不是作答人数**：交白卷的人也计入分母。所以一张有一半人交白卷的卷子，各题 P 值会整体偏低 —— 这是刻意的（空着就是没拿到分），但读数字时要记得区分「题难」和「人没做」。
35. **高低分组按总分切，不按单题切**：D 值用的是「总分前 27% / 后 27%」。这在总分可信的前提下成立；如果卷子里有一道题分值畸高（比如 100 分卷子里占 60 分），分组会被这一题主导，其余题的 D 值失真。每题分值建议尽量均衡。
36. **分析只统计已判分的答卷**：进行中的答卷不进统计，所以考到一半看分析，数字会随着交卷人数增加而变化。要一份定稿的分析，等考完并强制收卷后再看。
37. **每人只取最近一次答卷**：补考/重考的人只按最后一次算，与成绩册口径一致。如果某次补考成绩奇差，那次不会进分析 —— 换句话说，分析反映的是「最终成绩」而不是「所有尝试」。
38. **练习卷不支持逐题分析**：每人抽的题都不一样，横向比较没有意义，接口直接 400。这不是没做完，是刻意不做。
39. **选项分布按原始顺序展示**：学生看到的选项是洗过序的，但统计按选项 ID 归并、按 `sort_order` 排回 A/B/C/D。所以「B 只有 1 人选」说的是出题时那个 B，不是某个学生屏幕上的第二个选项。
40. **分析没有每题用时**：`attempt_item` 只记录最后一次保存时间，算不出每道题的耗时。要加得在开考时逐题打点（新增字段），当前结构不支持。平均用时是按整卷算的。
41. **浏览器崩溃时本地未同步的答案会丢**：`pagehide` 在崩溃场景不一定触发，队列在内存里随之消失。已经落盘的答案不受影响。帮助页按这个事实写，没有承诺「崩溃也不丢」。
42. **队列状态不写 localStorage**：交卷后应清空，持久化反而会污染下一次考试；崩溃恢复已由服务端的进行中答卷 + 已落盘答案覆盖。
43. **快照只在交卷那一刻有效**：交卷前所有请求全失败、交卷请求本身也失败时，答案就真的没了 —— 这时学生看到的是一次失败的交卷（服务端到点会惰性判分）。此时正确做法是重试交卷，页面会提示。
44. **重试会产生重复请求**：网络时好时坏时同一题可能被保存多次，但每次都是「最新值覆盖」，结果幂等。服务端不校验版本号，因为前端已保证同题串行。
45. **在线判定有 90 秒延迟**：学生关掉页面后，监考页要等 90 秒才会变成「掉线」。这是为了容错（前端 20 秒一次心跳，允许连丢 4 次）。想要更快可以调 `OFFLINE_AFTER_MS`，代价是网络抖一下就满屏飘红。
46. **心跳不做鉴权以外的校验**：它只刷新时间戳与回状态，不检查「你是不是还在同一台设备」。学生换浏览器登录会共用同一份答卷（按账号），监考页显示的仍是那个人。
47. **撤销违规不会把答卷退回答题状态**：已经因违规被强制交卷的，撤销只让次数退回去，答卷仍是 `submitted`、分数照旧。要不要补分是教务判断，系统不替你做。
48. **撤销的额度是实时的，但只在学生下次操作时生效**：学生页面靠 20 秒一次的心跳同步违规次数，所以撤销后最多要等 20 秒，学生端的「违规 2/3」才会退回「1/3」。
49. **监考视图不记录历史轨迹**：它只显示「此刻」。要看过程得导出答卷流水（`/api/attempts/export`），那里有每次交卷的时间与原因，但没有「几点几分掉线过」这类事件流。
50. **心跳字段在所有时间戳里最容易写错类型**：`last_seen_at` / `revoked_at` 必须是 `bigint`。用 `integer` 时 SQLite 全绿、MySQL 开考直接 500（`Out of range value`）——这是 v0.11 真实踩过的坑，见 `architecture.md` 6.12.5。
51. **审计日志不记学生的答题流水**：开考、存答案、交卷只在 `attempt` / `attempt_item` 里留时间戳，不进审计表。一学期几十万条答题记录会把真正要查的几条埋掉。唯一例外是系统自动收卷（`attempt.auto-close`），因为它无人操作却改了成绩。
52. **审计是旁路，写失败会静默丢**：`writeAudit` 内部吞掉所有异常，只往控制台打一行。宁可漏一条日志，也不能让「发布试卷」因为日志表写不进去而失败。极端情况（磁盘满、表被锁）下确实会丢，这是刻意的取舍。
53. **改代码新增路由时容易漏埋点**：没有全局 hook 兜底，靠人记得在路由里调 `audit()`。动作字典在 `server/src/audit/actions.ts`，加动作要同步那里，否则日志里会是个没中文标签的裸键名（服务端会打 `[audit] 未登记的动作键` 警告）。
54. **清理不可恢复，且没有自动清理**：程序不替学校决定留档期限。`POST /api/audit/purge` 只按传入的时间点删，删完就没了；清理动作本身会留一条 `audit.purge`，而这条永远删不掉。
55. **关键字搜索会把 `%` 当空格处理**：避免 LIKE 在 MySQL/SQLite 上两种转义行为打架。下划线保留（学号、用户名里全是），代价是它仍作为「任意单字符」通配符，可能多匹配几条。
56. **时间范围只有预设档位**（全部/今天/近 7/30/90 天）：自定义区间要引 dayjs，而它不是 web 的直接依赖（pnpm 严格模式解析不到）。要精确到某一天，用关键字或导 CSV 后筛。
57. **登录失败只记原因不记尝试的密码**：`detail.reason` 是 `no-such-user` / `bad-password` / `disabled`。量受登录限流约束（同用户名+IP 8 次/10 分钟、单 IP 30 次/10 分钟），不会把表刷爆。
